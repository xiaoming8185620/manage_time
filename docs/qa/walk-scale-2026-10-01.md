# 主角步态缩放定位与修复

先定位原因，随后按用户“尝试修复”的要求校准 `src/WalkingSprite.jsx` 的渲染比例；保留现有六帧 ImageGen 素材、帧周期及互动行为。

## 浏览器证据

同尺度静态对照：docs/qa/walk-scale.html。复用 WalkingSprite 与 PlayerCharacter，在 110×165 CSS 像素容器内并排展示站立和六个行走帧。

- 七个角色容器均为 110×165，行走 body transform 为 none。
- 正式温室页面行走时角色容器为 84.0234×126.031，body transform 为 none；外层 matrix 只有定位平移，没有 scale。
- 原始图集尺寸与代码声明一致：站立 1254×1254，两张步态均 1774×887，排除图像固有尺寸误读。

## 原因

WalkingSprite.jsx 用 88/(bottom-top) 逐帧归一化整体高度，再按鞋底与水平锚点定位。各帧高度范围 748—778 像素，得到的像素缩放比例存在约 4% 差异。然而两张独立生成的步态图集本身头部与上身比例不同：整体等高不等于同一体型。

读取原始 alpha >=128 的头发区域，按现有渲染公式计算，在 110px 角色容器内：

| 姿态 | 头发轮廓显示宽度 |
| --- | --- |
| 站立 | 44.53px |
| 行走 1 | 51.22px |
| 行走 2 | 50.46px |
| 行走 3 | 50.76px |
| 行走 4 | 46.98px |
| 行走 5 | 46.60px |
| 行走 6 | 46.73px |

开始行走相对站立头部可增宽约 15%；循环内前后半段头部宽度最大相差约 10%。六帧每帧 0.12 秒，总周期 0.72 秒，导致每半轮出现体型改变的观感。行走 CSS 已禁用 idle 呼吸动画；idle 最大约 1.5% 的纵向呼吸不是主要原因。

## 修复方向

先统一站立和六帧行走素材的头部、肩部、躯干比例；同一角色采用稳定的解剖尺寸基准与脚底锚点，保留抬腿造成的自然身高起伏。不要继续逐帧把可见包围盒机械拉到同一高度，也不要通过改变移动速度掩盖比例跳变。

## 已实施校准

- 以站立素材的头发宽度 184px / 身高 600px 为横向参照。前图集参考头宽 272px，后图集 242px，分别设置横向缩放，避免头部宽度在两个半周期之间跳变。
- 前图集参考身高 776px，后图集 750px；同一图集内纵向缩放固定，不再使用每帧的总高度计算缩放。保留鞋底坐标与水平骨盆锚点，只平移各帧到落点，保留自然起伏。
- 六帧与每帧 0.12 秒的节奏保持不变。容器、场景尺寸、移动路径、金币拾取逻辑及存档均未因本次修复改变。
