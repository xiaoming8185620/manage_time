# Python 家庭版

## 启动与访问

运行环境：Python 3.10 或更新版本。依赖见项目根目录 `requirements.txt`，当前用 Python 3.11、Flask 3.1、Waitress 3.0 验证。

```sh
python3 -m pip install -r requirements.txt
python3 app.py
```

默认监听 `0.0.0.0:4180`。在旧 Mac 本机先打开 `http://localhost:4180`，输入孩子的名字或昵称，点击“进入小镇”即完成首次创建并直接进入，无需密码或登录名。首次创建只允许在服务器本机完成。随后 iPad 或其他电脑连到相同家庭 Wi-Fi，用 `http://旧Mac的局域网IP:4180` 输入同一个名字继续进度。

家长在入口点击“家长看记录”进入成长手记，也不需要密码。家长与孩子是不同页面入口，不是身份验证边界，适用于本轮约定的可信家庭局域网。输错名字不会创建第二份存档或覆盖原进度；首尾空格与英文字母大小写不影响进入。旧版已经创建的小镇使用原孩子昵称继续，原任务、币数、记录和周报保留。

可指定监听地址、端口和数据位置：

```sh
python3 app.py --host 0.0.0.0 --port 4180 --data-dir data/family
```

这是家庭局域网服务，没有配置公网转发或域名。HTTP 适用于本轮选择的可信家庭网络；若以后开放到外网，需要另外配置 HTTPS 和访问入口。Mac 必须保持运行、网络连通；休眠或关机时其他设备无法访问，邮件也会延迟到恢复运行后。未改动 Mac 的休眠设置或安装开机启动项。

Python 直接提供 `dist/family` 中已构建的页面，不需要同时运行 Node 服务。**修改前端源码后**，才需要在开发电脑重新执行：

```sh
npm run build:family
```

现有 `npm run dev` / `npm run build` 仍是单机原型和既有 Sites 构建，保持原有接口。不要把 `dist/client` 当作家庭版目录；Python 使用 `dist/family`。

## 记录口径

- 所有日期、周次和投递时间按北京时间计算，不受 iPad 时区影响。周一至周日为一周。
- 任务有独立安排日期。今日安排只显示当天任务，同时列出过去尚未完成的任务。允许修改日期，原先的操作记录保留。
- 每次安排、开始、暂停、调整、记录进展、领币和建设都保留服务器时间。历史日记以当日截止时的快照展示；后来补记到旧日期的安排会标注补记时间。
- 完成数量和自报实际分钟按**完成发生的日期**计入，跨日完成不会重复计数。分类计划分钟按安排日期计入，因此两个数不是同一批任务的完成率。
- 小镇前台打开时长由可见页面每 15 秒报告一次，仅统计连续心跳；隐藏页面停止累计，超过 45 秒的失联间隔不补计，多标签或多设备重叠时段取并集。关闭页面可能少计最后一个心跳间隔。这不是学习、注意力或专注时长。
- 任务计时包含离开页面后仍在继续的时间，孩子回来再如实填写实际用时。不会将页面打开时长当作实际学习时长。
- 同账号约每 5 秒拉取最新进度。操作带版本号与唯一编号，过期版本不会覆盖另一设备的修改；网络中断可重试同一操作，不重复发币或建设。没有离线编辑同步。

## 周日 20:00 的周报

服务器每分钟检查一次，周日 20:00 后生成站内投递记录并发送邮件，通常在一分钟内开始处理。每个孩子、每一周只生成一份投递快照。停机后恢复时会补生成缺失的周报。

邮件包含任务清单、完成／部分完成／暂停状态、分类计划与自报用时、估时相关信息和温和回顾提示。**邮件是生成时快照**；周日 20:00 之后的动作继续出现在每日手记和站内实时周清单，已发出的邮件不反复重发。

发信配置：将 `mail-config.example.json` 复制为根目录 `mail-config.json`，填写邮箱提供的 SMTP 地址、端口、用户名、授权码、发信地址，以及唯一固定收件地址 `recipient`。支持 465 TLS 或 587 STARTTLS，证书必须有效，不允许关闭 TLS 验证。初始化不再填写邮箱；家长的“邮件与存档”页面只读显示固定收件地址，可以开启或关闭周报邮件。配置文件改好后下一轮自动读取，不需要前端重建；已打开的设置页面刷新后显示新配置。

收件地址只以此文件为准，数据库里旧版页面保存的邮箱不再参与发信；即使直接调用设置接口也不能修改固定地址。示例中的 `recipient` 默认留空，等待填写用户指定的邮箱，不会回退到旧地址或发信邮箱。

```json
{
  "host": "邮箱提供的SMTP服务器",
  "port": 465,
  "username": "发信邮箱账号",
  "password": "邮箱的SMTP授权码",
  "from": "发信邮箱地址",
  "recipient": "固定接收周报的邮箱地址"
}
```

不要提交真实 `mail-config.json`；它已列入 `.gitignore`，建议仅允许当前用户读取（`chmod 600 mail-config.json`）。不要把 SMTP 授权码发到聊天中。收件人可与发信邮箱相同。

- 未填收件邮箱或 SMTP 配置：显示“邮件待配置”，站内功能正常。
- 明确被邮箱拒绝：最多尝试 3 次，间隔至少 15 分钟。
- 发送超时、确认丢失或进程在发信途中退出：标记“发送结果待确认”，不自动重发。家长检查收件箱后可确认重试，避免重复邮件。
- SMTP 返回接受不保证最终进入收件箱，首次实际投递还需查看收件箱或垃圾箱。本轮只用模拟发信器测试，未连接真实邮箱。

## 数据与原型迁移

数据默认在 `data/family/town.sqlite`，包含孩子昵称、任务、日记、页面使用区间和周报投递状态。新建居民不保存密码；兼容旧数据库中的原居民 ID，不重置数据。会话使用 HttpOnly Cookie；孩子会话和家长查看会话分别开放相应操作，家长入口无需密码。

从旧原型迁移：在原型右上角“玩法与存档说明”中点“导出小镇存档”；输入名字创建**全新的小镇**后进入“成长手记 → 名字与存档”，选择该 JSON 文件。导入必须在认识小乖和创建任务之前，已有服务器进度不会被覆盖。导入不会删除或改变原浏览器存档，旧版正在进行的计时会转为暂停。旧记录没有历史操作流，因此不伪造导入前的使用时长或每次动作。

服务器运行后每天留一份一致的 SQLite 备份在 `data/family/backups`，保留最近 14 份；自定义 `--data-dir` 时备份也跟随该目录。建议额外复制到另一块磁盘。需要恢复时先停止 Python 服务，保留现有数据库目录，再用选定备份恢复为 `town.sqlite`；不要在运行期间直接覆盖 SQLite 文件或只复制主文件而忽略 WAL。

## 验证与范围

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
npm test
npm run build:family
npm run build
```

服务器用例覆盖身份与权限、跨设备冲突、跨天快照、重复操作、使用时长去重、周报时点与停机补生成、邮件异常与备份。Node 可用时，还会比对原 JS 游戏规则与 Python 服务端结果。

当前是单家庭、一个孩子；未增加公开注册、多家庭隔离、多个孩子切换、系统通知推送、社交分享或支付。未验证旧 Mac 实机与真实 iPad Safari，也未实际配置用户邮箱。

实现依据：[Flask 的 Waitress 部署说明](https://flask.palletsprojects.com/en/stable/deploying/waitress/)、[Python SQLite 备份接口](https://docs.python.org/3.13/library/sqlite3.html)、[Python SMTP 客户端](https://docs.python.org/3.12/library/smtplib.html)。

## 场景照料与成长

花草免费浇水；付费照料每档 3 星球币，最多三档，增加的枝叶与花朵永久保存。非植物对象每天最多付费照料一次。费用、次数和余额由 Python 服务器核对，同一操作重试不会重复扣币；多设备的旧状态不会覆盖新成长。每日手记显示对象、动作、费用和阶段。旧存档没有照料记录时从初生开始，原有任务、建筑和余额不变；导入含照料记录的单机存档会同时扣除历史照料支出，避免返还已使用的币。

天气服务无需 API Key 或额外依赖：Python 同源接口固定同步杭州天气，需可联网访问 api.open-meteo.com。离线会展示上次天气及时间，过期后使用默认晴景；不影响 SQLite 存档和任务。
